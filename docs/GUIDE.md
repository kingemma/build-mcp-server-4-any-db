## 0. 五步模型

这个工具只做一件事：在 **AI 客户端** 和 **数据库** 之间装一道可验证的权限闸门。

```
连接数据库  →  配置权限  →  验证生效  →  讲清业务  →  接入 AI 客户端
（它能看什么）   （谁能看什么）   （真的拦住了）  （这是什么生意）  （Claude / Cursor / 任意 MCP 客户端）
```

产出是一个 MCP 端点（`http://127.0.0.1:<端口>/api/v1/mcp`）。AI 通过 MCP 工具查数据时，
GraphJin 按你配的角色规则拦截：看不到的表查不到，行过滤的行取不出来，写 / 删按数据源档位挡掉。
第四步把人类维护的业务语境（术语 / 概念 / 关系 / 规则 / 指标 / 样例）一并交给 AI，让它先是懂业务的助手，
然后才是会查表的工具。每一步都可验证、可回滚。

> 应用内的「使用向导」就是这条动线，首次进入自动弹出，右下角悬浮按钮可随时再打开。

## 1. 启动应用

第一次用只需三步（详细命令见 README「本地启动」）：

```bash
npm install                 # 装依赖
npm run prepare:binaries    # 准备并校验 GraphJin 二进制
npm run electron:dev        # 启动桌面端（或 npm run dev 纯浏览器调试）
```

启动后默认落在**欢迎页**，上面有三步状态卡片和「一键体检」——不确定环境是否就绪就先点体检，
它会逐项告诉你 GraphJin 二进制 / 后端 / 实例 / 数据库 / 角色是正常还是异常。

三步卡片按真实证据判定（连过库 / 写过权限 / 生成过接入配置），刷新页面也不会丢。
实例停着时权限状态改读 `dev.yml`（GraphJin 会把 `access` 回写进去）；连文件都读不出来时
卡片显示 **「未确认」**——那表示「看不到」，不是「没做」。

## 2. 先跑一键演示（可选但推荐）

没有现成数据库、或想先看效果：欢迎页点 **「一键演示」**。

平台会自动完成：

1. 建一个演示 SQLite 库 `orders.db`，里面已有 `customers` / `orders` 示例表和真实数据；
2. 生成项目配置 `dev.yml`，预配好 `analyst` 只读角色：写 / 删被挡住，读带行过滤
   （`owner_code` 等于当前用户才可见）；
3. 拉起 GraphJin，右侧立刻列出拿到的库、角色、表和端点。

接着到 **MCP Client** 页点「测试全部库」，再跑一条示例查询，就能看到数据真的被读出来——
此时权限已经在生效。看完可以到「数据库连接」删掉演示连接，随时可重来。

## 3. 连接自己的数据库

到 **数据库连接** 页，填连接名、类型和连接信息：

| 类型 | 怎么填 |
|:--|:--|
| SQLite | 录入方式选「文件路径」，填已有的 `.db` 文件 |
| PostgreSQL / MySQL 等 | 填主机、端口、库名、用户、密码 |
| TiDB 等兼容库 | 选对应的 postgres / mysql 协议类型接入 |

「项目目录」填一个空目录（如 `projects/myapp`），GraphJin 的 `dev.yml` 会写在这里。
带密码的连接会用数据目录下的 `keystore.key` 加密保存，不会明文落盘。

1. 点 **「测试连接」** —— 通过后自动保存到本地列表；
2. 点 **「启动」** —— 平台创建/合并 `dev.yml` 并拉起 GraphJin；
3. 到 **Schema 浏览器** 确认表、列、关系已经被发现。

## 4. 配置权限

到 **权限矩阵**，分两层配，先档位后规则：

1. **数据源访问**：每个库的读 / 写 / 删档位（如只读库把写和删设为 blocked）、owner 列、表分类；
2. **角色读规则**：添加角色（如 `analyst`、`reporter`），给表配可见性和读规则——
   行过滤（如只看自己 `owner_code` 的行）和列管控（隐藏敏感列）。

点 **「应用到 GraphJin」** 后会先展示 diff，确认才写入；写入前自动保存快照，随时可回滚。

> `admin` 是平台保留角色：不进矩阵、不受限制规则约束、回滚不会删它。别拿它当业务角色用。

行过滤里的 `$user_code` 之类的变量来自调用方身份。AI 走 MCP 时**不透传**用户标识，
所以 MCP 路径上行过滤不生效，只有角色级规则生效——这正是要在下一节验证的边界。

## 5. 验证权限真的生效

不要只看配置写进去了，要跑真查询：

- **MCP Client** 页：选角色 → 「测试全部库」逐库探活 → 跑示例查询。
  示例查询按当前库的真实表名生成，点一下就填进编辑器，不用自己拼 GraphQL；
  下方「调用示例」给出 `execute_graphql` 等工具的参数 JSON，可直接复制给 AI 客户端。
- **策略预览** 页：看当前生效的完整策略和与上次的 diff，确认规则真的挂上了。
- 换个受限角色再查一次敏感表——查不到 / 行数变少，才是权限生效的证据。

## 6. 把「这是什么生意」讲给 AI 听（业务本体论）

Schema 只描述「怎么连表」，不描述「这是什么生意」。AI 缺的从来不是查询能力，而是新同事
入职几天才能摸清的东西。到 **业务本体论** 页分六层维护，**先选数据库**——每个库各有自己的
一套，同一个说法在两个库里可以是两回事：

| 层 | 写什么 | 例 |
|:--|:--|:--|
| **术语** | 说法 ↔ 表/列，可带值域 | 「买家」= 某张表；绑定列后列出真实取值 `paid`(已支付) / `refunded`(已退款) |
| **概念** | 实体含义与边界，可跨表 | 订单 = 购买意图，支付后才成为履约单；可标主键列与显示列 |
| **关系** | 外键的业务叫法与方向 | 下单人：`orders.customer_id → customers.id`，many-to-one |
| **规则** | 不变量与状态机，带强度、可执行形态、判据 | `[enforce]` 读取时只看未作废：形态=读筛选 · `{ status: { _eq: "voided" } }` |
| **指标** | 命名聚合 + 粒度 / 单位 / 窗口 / 可执行片段 | 履约时长 = 粒度每运单 · 单位小时 · 窗口 `picked_up_at` |
| **样例** | 问题 → 验证过的查询 | 「上月各站点平均履约时长」→ 一段能直接跑的 GraphQL |

「关联表」是下拉复选，候选来自当前所选库的 Schema，不用手填表名；**关系**更方便——直接从
现存外键里选一条，两端自动填好，不用手敲六个字段。同一张表有三条外键时（下单人 / 承运商 /
付款方），只有这一层说得清「按客户统计」到底按哪条。

系统不认识的行业信息放 **扩展属性**（每行一条「键=值」）：它只被原样转交给 AI，不解释也不
校验——所以不必为了某个行业给代码加字段，也不必自造新的条目类别。

页面下方有「送给 AI 的语境」实时预览，只放 schema 里读不到的东西——表结构、列、外键一概
不写（那些 AI 用 `query_catalog` 自己拿）。

落库时记的是**规范形式**（`库.schema.表`）：同一个库里两个 schema 各有一张同名表时，
只有写全才指得准。表被改名或删掉后本体论不会自己发现，所以页面里还有一个 **「一致性体检」**
——拿条目和真实 schema 对一遍，报出「引用的表已不存在」「强制规则没有可判定的表达式」
「指标只有说明没有计算式」「绑定的列不存在」「关系的两端对不上」这类问题，并给出能直接照抄的
改法。实例没启动时只跑不依赖 schema 的那几条，并明确告诉你跳过了几项（少查几项却显示
「没问题」最误导）。

**不想从空表格开始**：点 **「从 schema 起草」**，页面会列出库里已经有、本体论还没覆盖的东西
——没有概念的表、没有关系的外键、有注释却没有术语的列。点「起草」只把候选填进表单，**不会
保存**：定义与边界仍然得人来写，自动生成的空定义只会稀释真正的知识。

术语的「值域」旁边有 **「从数据扫描」**：对绑定列抽 200 行、去重后填进去。它只接受低基数列
——取值太多、太长或含等号/换行的列会被拒绝，避免把姓名、金额、JSON 这类值带进每一次对话的
上下文（值域会随本体论下发给所有 AI 客户端，这不是小事）。

**样例还可以被评测**。给样例写上「期望表 / 期望列 / 期望取值 / 不应出现」之后点 **「运行评测」**，
平台用确定的规则核对三件事：这段查询还能不能跑通、它和声明的期望是否一致、以及**问题需要的表
本体论讲过了没有**（没人讲的表，模型只能猜）。它不评价模型答得好不好——那需要真模型和真答案，
所以「评测通过」的含义是「这份语境还站得住」，不是「AI 很懂业务」。

**「强制」不再只是文字**。给规则选一种可执行形态（读筛选 / 隐藏列 / 整表禁读 / 全局只读）之后，
点 **「编译成权限」** 会算出补丁：哪些角色会多一条行过滤、哪一列会从列清单里消失、哪张表会被
全局屏蔽。它**只算不写**——先看 diff，再点「应用补丁」，写入走的是权限页同一条路径，并且自动
存快照可回滚。GraphJin 表达不了的规则（写不变量、状态机）不会被编译，直接列为冲突：宁可说
「做不到」，也不假装编出来一个东西。

**怎么送到 AI 手里**：经 MCP 网关，分三档。

1. **握手给目录**：有哪些库、每类多少条、**硬约束（强制规则）全文**、以及怎么取细节。
   目录有长度上限，超了会截断并注明——它占的是每次会话的固定预算，条目越多越要克制。
2. **按需取细节**：`business_ontology` 不带参数取全文，带 `database` / `kind` 取一节，
   带 `query` 按问题里的说法**检索**（返回命中理由：别名、表名、还是说明里出现）。
3. **看一个对象**：`describe_business_object({name})` 给出它的定义、涉及的列语义、沾到同一批表
   的关系 / 规则 / 指标 / 样例——比读全文便宜得多。

**送什么还看身份**：被屏蔽的表、以及「仅管理员可读」的表（对非管理员），它们的条目不会下发给
这个角色的客户端——数据和语义一起受限。判定用的是 dev.yml 里的 `sources[].access`，权限改完
立即生效。

单条正文超过 1000 字时，渲染会截断并标注，体检里也会提醒拆分：进 prompt 的每条都有成本。

所以在「接入 AI」页要打开 **「经平台网关下发」** 并填上访问令牌——直连 GraphJin 的客户端
只能看到表结构。这条路同时是行过滤生效的唯一途径（身份来自令牌）。

> 一条都没维护时，网关保持纯透传，既有客户端完全不受影响。

## 7. 接入 AI 客户端

到 **接入 AI** 页：

1. 需要业务本体论 / 行级隔离时，先打开 **「经平台网关下发」** 并粘贴访问令牌
   （令牌在「用户与组织」页签发，决定客户端以谁的身份调用）；
2. 选你的客户端（Claude Desktop / Claude Code / Cursor 等），卡片上直接给出配置文件位置
   和可复制的 `mcpServers` 片段；命令行接入的 `graphjin mcp add` 命令也一并给出；
3. 粘进客户端配置，重启客户端；
4. 回到页面点 **「自检」** —— 平台用 MCP 协议走一遍工具列表，确认客户端能连上。

> 限制：直连 GraphJin 时 MCP 不转发用户标识，AI 只能按角色拿到数据，拿不到「某个人的行」
> 这种粒度。需要行级隔离必须走网关（身份来自令牌）。

## 8. 日常使用

| 场景 | 去哪 |
|:--|:--|
| 加人、建组织、给成员映射角色 | **用户与组织** |
| 给 AI 补业务语境（术语 / 概念 / 关系 / 规则 / 指标 / 样例） | **业务本体论** |
| 改权限后确认 diff、回滚上一次写入 | **策略预览**（写入前自动存快照） |
| 看端点 / 进程状态、手动启停 | **运行状态** |
| 环境体检（二进制 / 后端 / 实例 / 库 / 角色） | **欢迎页 · 一键体检** |
| 旧项目（`databases:` 旧格式） | 启动时自动迁移成 `sources:`，原文件留 `.bak`，失败自动回滚 |
| 版本、端口等 | **设置** |

## 9. 出问题先看这里

| 现象 | 处理 |
|:--|:--|
| 一键体检报红 | 按报红项定位：二进制缺失跑 `npm run prepare:binaries`；实例没起先在「运行状态」启动 |
| 启动后立刻退出 | 看「运行状态」的日志和项目目录下 `dev.yml`；常见是端口冲突或数据库连不上 |
| AI 客户端连不上 | 先在「接入 AI」点自检；再确认客户端配置里的 URL 端口和当前实例一致 |
| 查不到表 / 行数不对 | 先确认当前角色的读规则；MCP 路径下行过滤不生效，只有角色级规则生效 |
| 带密码的连接保存失败 | 确认数据目录下 `keystore.key` 存在；丢失后旧连接需重新录入密码 |

更多命令行排查（端口占用、Node 版本、二进制校验）见 README「常见问题」。
